# ДЗ №3. Проектирование API-контрактов

OpenAPI 3.1 для сервиса «Библиотека». Контракт описывает каталог книг, читателей, выдачу и возврат экземпляров. Реализация HTTP-сервера в эту работу не входит.

## Файлы

| Файл | Назначение |
|---|---|
| `openapi.yaml` | Основной контракт: 14 операций, схемы, примеры, ошибки, JWT и бизнес-правила |
| `STYLE.md` | 10 правил проектирования API |
| `REVIEW.md` | Саморевью по требованиям и рубрикатору задания, ограничения проверки |
| `validate.py` | Проверка OpenAPI, ссылок, примеров, операций и недопустимых входных данных |
| `requirements-dev.txt` | Версии инструментов проверки |

## Операции

Базовый адрес для локальной реализации: `http://localhost:4010/v1/`. Он указан в `servers`; сам файл спецификации сервер не запускает.

| Ресурс | Методы |
|---|---|
| `/books` | GET (список), POST (создание) |
| `/books/{id}` | GET, PATCH, DELETE |
| `/readers` | GET (список), POST (создание) |
| `/readers/{id}` | GET, PATCH, DELETE |
| `/loans` | GET (список), POST (выдача с Idempotency-Key) |
| `/loans/{id}` | GET |
| `/loans/{id}/return` | POST (возврат без тела) |

`PATCH` реализует Update из CRUD: изменяются только переданные поля. Полная замена через PUT не предусмотрена. Выдачи не удаляются и произвольно не редактируются.

## Проверка на Windows

В PowerShell из папки `library-api`:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe validate.py
```

Активация окружения не обязательна. Скрипт завершится с ненулевым кодом при ошибке. Проверяются структура OpenAPI 3.1, ссылки, JSON Schema, примеры запросов/ответов, запрещённые поля, неверные даты/UUID и состав операций. Проверка не исполняет описанные в контракте транзакции, JWT, срок хранения ключей и сравнение даты с текущим временем: для этого нужна будущая реализация сервиса.

Спецификацию можно открыть в инструменте с поддержкой OpenAPI 3.1. Нормативная основа: [OpenAPI 3.1.0](https://spec.openapis.org/oas/v3.1.0).

## Списки и ошибки

- Книги: фильтры `title`, `author`, `isbn`, `published_year`, `available`; сортировка по `title`, `author`, `published_year`, `id`.
- Читатели: `full_name`, `email`; сортировка по `full_name`, `registered_at`, `id`.
- Выдачи: `status`, `book_id`, `reader_id`; сортировка по `loaned_at`, `due_date`, `id`.
- Везде есть `page`, `page_size`, `sort`. Пример: `GET /v1/loans?status=overdue&sort=due_date&page=1&page_size=20`.
- `active` включает просроченные; `overdue` означает `returned_at == null` и `due_date < сегодня UTC`. В день due_date просрочки ещё нет.
- Ответ списка: `items` и `pagination` с `page`, `page_size`, `total_items`, `total_pages`. Новые записи между запросами могут сдвигать страницы.

| HTTP | error.code | Ситуация |
|---|---|---|
| 400 | INVALID_REQUEST | Нечитаемый JSON, неизвестный query-параметр, отсутствующий ключ |
| 401 | UNAUTHORIZED | Нет действующего Bearer JWT |
| 404 | NOT_FOUND | Не найден ресурс или книга/читатель для выдачи |
| 409 | CONFLICT | Дублирование ISBN/email или запрос с ключом ещё выполняется |
| 409 | BUSINESS_RULE_VIOLATION | Нет экземпляров, уже 5 выдач, активные выдачи при удалении, недостаточный фонд |
| 409 | IDEMPOTENCY_MISMATCH | Ключ уже используется с другим телом |
| 415 | INVALID_REQUEST | Тело не в формате application/json |
| 422 | VALIDATION_ERROR | Неизвестное поле тела, неверный UUID/формат/тип/ISBN |
| 422 | BUSINESS_RULE_VIOLATION | due_date сегодня или в прошлом |
| 503 | SERVICE_UNAVAILABLE | Временный сбой, повтор после Retry-After |

## Поведение выдачи и повторов

1. Сервер проверяет JWT, заголовок, JSON и схему. В `LoanCreate` разрешены только `book_id`, `reader_id`, `due_date`.
2. Ключ резервируется в области пользователя `sub`, метода и пути. Пробелы JSON и порядок полей не влияют на равенство, значения строк влияют.
3. Существующая книга, существующий читатель, доступный экземпляр, менее 5 активных выдач и будущая дата проверяются при первой обработке. Проверки состояния и запись защищены общей транзакцией.
4. Результат 201 или доменный 404/409/422 фиксируется вместе с результатом операции и хранится 24 часа после завершения. Replay возвращает исходные статус, тело и прикладные заголовки. Изменение даты, фонда или последующий возврат не меняют сохранённый ответ.
5. Другое тело с тем же ключом: 409 IDEMPOTENCY_MISMATCH. Одновременный идентичный запрос: 409 CONFLICT с `request_in_progress`, заголовок `Retry-After: 1`; повторить исходный запрос позже.
6. Replay не продлевает TTL. После истечения 24 часов ключ считается новым. Незавершённые записи требуют восстановления, а не удаления как завершённые; временный 503 не становится окончательным результатом.
7. Возврат через POST по id идемпотентен по эффекту: первый раз фиксирует время, повтор возвращает прежний результат и не освобождает второй экземпляр.

Полная нормативная политика находится в `description` операции `createLoan`. Схема OpenAPI описывает её, но сама не обеспечивает выполнение.

## Примеры curl для будущей реализации

Ниже показан формат запросов, а не отчёт о запущенном сервере. Для выполнения нужны реализация на localhost:4010, действующий JWT сотрудника и существующие UUID книги/читателя. Примеры в YAML зафиксированы на дату 2026-10-18 UTC; в командах дата вычисляется автоматически.

```powershell
# Сначала установите $env:LIBRARY_TOKEN в действующий токен своей реализации.
curl.exe "http://localhost:4010/v1/books?available=true&sort=title&page=1&page_size=20" `
  -H "Authorization: Bearer $env:LIBRARY_TOKEN"

$bookId = '11111111-1111-4111-8111-111111111111' # замените на существующий id
$readerId = '22222222-2222-4222-8222-222222222222' # замените на существующий id
$key = [guid]::NewGuid().ToString()
$payload = @{
    book_id = $bookId
    reader_id = $readerId
    due_date = [DateTime]::UtcNow.AddDays(14).ToString('yyyy-MM-dd')
} | ConvertTo-Json -Compress
# Файл избегает различий обработки кавычек между версиями PowerShell.
[IO.File]::WriteAllText((Join-Path $PWD 'loan-request.json'), $payload)

curl.exe -i -X POST 'http://localhost:4010/v1/loans' `
  -H "Authorization: Bearer $env:LIBRARY_TOKEN" `
  -H 'Content-Type: application/json' `
  -H "Idempotency-Key: $key" --data-binary '@loan-request.json'
# Повторите эту же curl-команду с тем же $key и файлом: ожидается replay.

curl.exe 'http://localhost:4010/v1/loans?status=overdue&sort=due_date' `
  -H "Authorization: Bearer $env:LIBRARY_TOKEN"

# $loanId — id из ответа создания выдачи.
curl.exe -i -X POST "http://localhost:4010/v1/loans/$loanId/return" `
  -H "Authorization: Bearer $env:LIBRARY_TOKEN"
```

## Дополнительное задание

Выполнены два пункта: Bearer JWT в `securitySchemes` с глобальным `security` и таблица совместимости изменений ниже. Mock-сервер не заявлен как выполненный бонус. Искусственное устаревшее поле не добавлялось.

### Совместимость при развитии API и переходе к v2

Совместимое изменение сохраняет работу существующего корректного клиента v1 без изменений. Несовместимое вводится по новому `/v2/` с периодом параллельной поддержки v1.

| Изменение | Совместимость | Причина / действие |
|---|---|---|
| Новая независимая операция | Да | Старые операции сохраняются |
| Необязательный фильтр, по умолчанию не влияющий на выдачу | Да | Прежние запросы имеют прежний результат |
| Новое необязательное поле ответа `publisher` | Да, при текущем правиле чтения | Клиенты v1 обязаны игнорировать неизвестные поля ответа |
| Необязательное поле запроса с прежним поведением по умолчанию | Да для старых клиентов на новом сервере | Старые запросы остаются допустимыми; новые клиенты должны дождаться обновления сервера |
| Удаление или переименование `full_name` в `name` | Нет | Старые запросы/обработчики теряют поле; только v2 |
| Изменение `id` из UUID-строки в число | Нет | Меняется тип и формат; только v2 |
| Новый обязательный параметр/поле запроса | Нет | Прежние запросы перестают проходить валидацию |
| Новое значение закрытого enum `error.code` | Потенциально нет | Сгенерированные клиенты с исчерпывающим enum могут перестать разбирать ответ; требуется согласованная миграция |
| `page/page_size` заменены на cursor | Нет | Меняется способ обхода и структура метаданных; v2 либо новая отдельная операция |
| `due_date` из date в date-time, смена часового пояса | Нет | Меняются формат и границы просрочки |
| Снижение page_size max со 100 до 50 или лимита выдач с 5 до 3 | Нет | Ранее допустимые запросы будут отклоняться |
| Изменение TTL ключа с 24 часов на 1 час | Нет | Повторы могут создать дубликаты вместо replay |
| Смена POST возврата на DELETE или успеха 201 на 200 | Нет | Меняется метод либо согласованный статус |

## Принятые решения

- ISBN-13 без разделителей и с проверкой контрольной цифры. Email в этом учебном контракте нормализуется в нижний регистр целиком.
- Удаление скрывает книгу/читателя, но сохраняет историю выдач. GET удалённого ресурса возвращает 404.
- Все аутентифицированные сотрудники имеют одинаковые права; управление учётными записями вне задания.
- Слайдов 29–32 среди исходных материалов нет. `REVIEW.md` опирается на требования и подробный рубрикатор приложенного задания, без утверждения о дословном совпадении со слайдами.
