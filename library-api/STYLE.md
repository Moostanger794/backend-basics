# Правила Library API

1. **Ресурсы и версия.** Базовый URL заканчивается на `/v1/`. Пути используют существительные во множественном числе и kebab-case; имена JSON и query-параметров — snake_case. Версия не дублируется в `paths`.
2. **Методы и статусы.** GET читает (200), POST создаёт (201 + Location), PATCH частично обновляет (200), DELETE удаляет (204 без тела). Возврат книги — `POST /loans/{id}/return`, история выдачи сохраняется.
3. **Раздельные схемы.** Create/Update отделены от ответов. `additionalProperties: false` запрещает неизвестные поля запросов. `id`, `registered_at`, `loaned_at`, `returned_at`, `available_copies` клиент не задаёт. PATCH не принимает `{}` и null; пропущенные поля не меняются.
4. **Типы и время.** Идентификаторы — UUID, календарные даты — ISO `date`, моменты — RFC 3339 `date-time` в UTC. В OpenAPI 3.1 nullable задаётся `type: [string, 'null']`. Только `returned_at` допускает null. Проверку будущей даты и состояния базы выполняет сервер.
5. **Коллекции.** Ответ — `{items, pagination}`. `page >= 1`, `page_size` от 1 до 100 (по умолчанию 20). Фильтры сочетаются через AND, `sort=-field` означает убывание, при равенстве — `id` по возрастанию. Пустой результат и страница за концом — 200 с пустым массивом.
6. **Ошибки.** Всегда `ErrorResponse`: `error.code`, `message`, `details`, `request_id`. 400 — форма запроса; 401 — аутентификация; 404 — отсутствие; 409 — конфликт состояния; 415 — формат тела; 422 — валидация/будущая дата; 503 — временный сбой. Логику клиента строить по `code` и `details.reason`, не по тексту `message`.
7. **Выдачи и согласованность.** Проверка доступных экземпляров, лимита 5 выдач и запись — одна транзакция. `available_copies = total_copies - active_loans`; просроченные выдачи тоже активны. Удаление и изменение фонда синхронизированы с выдачами. Повторный возврат не изменяет остаток и время возврата.
8. **Идемпотентность.** `POST /loans` требует Idempotency-Key. В области `sub + метод + путь` результат хранится 24 часа после завершения. То же тело воспроизводит статус, тело и прикладные заголовки; другое тело — 409 IDEMPOTENCY_MISMATCH; незавершённый повтор — 409 CONFLICT + Retry-After. Подробности фиксации, TTL и ошибок — в `createLoan`.
9. **Аутентификация.** Все операции требуют Bearer JWT сотрудника. Токен проверяется и при replay. За пределами localhost использовать HTTPS; токены не помещать в URL и примеры репозитория. Выпуск токенов в этот контракт не входит.
10. **Развитие контракта.** Клиенты игнорируют новые поля ответов; запросы остаются строгими. Удаление/переименование полей, изменение типов, семантики и обязательности требует новой версии. Для каждой операции нужны уникальный operationId, tag, описания и согласованные со схемами examples.
