# Саморевью Library API

Основание: требования и рубрикатор ДЗ №3 «Проектирование API-контрактов». Слайды 29–32 не предоставлены: этот документ не выдаёт реконструированный чек-лист за дословный чек-лист лекции. Для проверки точного соответствия слайдам потребуется их текст.

## 1. Ресурсы, методы и HTTP

- [x] `servers` содержит `http://localhost:4010/v1/`; версия не повторяется в `paths`.
- [x] Книги и читатели: создание POST, чтение коллекции/элемента GET, частичное обновление PATCH, удаление DELETE.
- [x] Выдачи: POST `/loans`, GET `/loans`, GET `/loans/{id}`, POST `/loans/{id}/return`.
- [x] Возврат не реализован через DELETE; история не уничтожается.
- [x] Создание возвращает 201 и Location; чтение/обновление/возврат — 200; удаление — 204 без content.
- [x] Ошибки 400/401/404/409/415/422/503 имеют определённую семантику; нет «200 на всё».
- [x] Все 14 операций имеют уникальный operationId, summary, description и тег Books/Readers/Loans.
- [x] Пути используют множественное число и допускают kebab-case; в путях нет snake_case. JSON и query-параметры используют snake_case.

## 2. Схемы и валидация

- [x] Book содержит id, title, author, isbn, published_year, total_copies, available_copies.
- [x] Reader содержит id, full_name, email, registered_at.
- [x] Loan содержит id, book_id, reader_id, loaned_at, due_date, returned_at.
- [x] Есть отдельные BookCreate/BookUpdate, ReaderCreate/ReaderUpdate, LoanCreate.
- [x] Все схемы входного тела имеют `additionalProperties: false`.
- [x] `available_copies` только в Book, с `readOnly: true`; запрос не может задавать остаток. Другие серверные поля также отсутствуют во входных схемах.
- [x] Обязательные поля ответов указаны явно, в том числе returned_at даже при значении null.
- [x] Использован синтаксис OpenAPI 3.1 `type: [string, 'null']`, а не устаревший `nullable`.
- [x] UUID, email, date и date-time имеют format; строки, числа и размеры коллекций ограничены.
- [x] PATCH сохраняет пропущенные поля, запрещает `{}`, null и серверные поля.
- [x] ISBN-13 проверяется по форме схемой, а контрольная цифра и уникальность — будущим сервером. ISBN примера дополнительно проверяется скриптом.
- [x] Дополнительные поля ответа допустимы; правило клиента игнорировать их согласовано с таблицей совместимости.

## 3. Коллекции и ошибки

- [x] Каждая коллекция имеет фильтры, sort, page и page_size.
- [x] Фильтры сочетаются через AND, описана точность/регистрозависимость поиска.
- [x] Описаны допустимые поля сортировки, значения по умолчанию и tie-breaker по id.
- [x] Пагинация содержит total_items и total_pages после фильтрации; пустой результат — 200, а не 404.
- [x] Указано ограничение offset-пагинации: изменения между запросами могут сдвигать страницы.
- [x] `GET /loans?status=overdue`: активная выдача с due_date раньше сегодняшней даты UTC; день due_date включён в допустимый срок.
- [x] Единая ErrorResponse использована у всех описанных ошибок.
- [x] В enum есть все шесть обязательных кодов: INVALID_REQUEST, NOT_FOUND, VALIDATION_ERROR, CONFLICT, BUSINESS_RULE_VIOLATION, IDEMPOTENCY_MISMATCH. Для бонуса JWT и временных сбоев добавлены UNAUTHORIZED и SERVICE_UNAVAILABLE.
- [x] `details.field` локализует ошибку, `details.reason` даёт машинно-читаемую причину, request_id помогает диагностике.

## 4. Бизнес-правила и конкурентность

| Сценарий | Ожидаемый контрактом результат | Где закреплено |
|---|---|---|
| available_copies = 0 | 409 BUSINESS_RULE_VIOLATION, no_available_copies | createLoan, пример NoCopies |
| У читателя 5 активных выдач, в том числе просроченные | 409 BUSINESS_RULE_VIOLATION, active_loan_limit | createLoan, LoanLimit |
| Два читателя одновременно запрашивают последний экземпляр | Только одна транзакция может создать выдачу; вторая получает конфликт остатка | createLoan, транзакция и блокировки |
| У читателя 4 выдачи, одновременно поступают 2 новые с разными ключами | Только одна может стать пятой | createLoan, блокировка читателя |
| due_date сегодня/в прошлом | 422 BUSINESS_RULE_VIOLATION | LoanCreate.due_date, createLoan, PastDueDate |
| Удаление книги/читателя с активной выдачей | 409 BUSINESS_RULE_VIOLATION, active_loans_exist | deleteBook/deleteReader |
| total_copies меньше числа активных выдач | 409 BUSINESS_RULE_VIOLATION | updateBook, CopiesBelowLoans |
| Возврат активной или просроченной выдачи | 200, время назначает сервер, освобождается один экземпляр | returnLoan |
| Повторный/конкурентный возврат | 200, прежний returned_at, остаток не увеличивается повторно | returnLoan |
| Удаление после завершения всех выдач | 204, ресурс скрыт, история выдач сохранена | deleteBook/deleteReader, getLoan |

Это проверка полноты описания сценариев; без реализации сервера она не доказывает выполнение транзакционных гарантий.

## 5. Idempotency-Key

- [x] Обязателен на POST `/loans`, имеет длину и допустимый алфавит.
- [x] Определена область: JWT sub + метод + путь в v1.
- [x] Определено сравнение JSON: порядок ключей и пробелы несущественны, значения сравниваются; дубли ключей запрещены.
- [x] Повтор с тем же телом воспроизводит HTTP-статус, байты тела, прикладные заголовки, в том числе Location.
- [x] Транспортные Date/Connection/Transfer-Encoding могут отличаться; request_id исходной ошибки сохраняется.
- [x] Replay не пересчитывает дату/остатки/лимит, но каждый раз требует действующего JWT того же sub.
- [x] Другое тело — 409 IDEMPOTENCY_MISMATCH; исходный результат не заменяется.
- [x] Конкурентный идентичный запрос — 409 CONFLICT, request_in_progress, Retry-After: 1; не создаёт вторую выдачу.
- [x] Хранятся 201 и доменные 404/409/422, полученные после структурной валидации. Ошибки формы и временные ответы не подменяют окончательный результат.
- [x] TTL равен 24 часам от завершения; replay не продлевает TTL; после истечения ключ считается новым.
- [x] Описано восстановление незавершённого запроса и атомарное сохранение выдачи вместе с результатом, чтобы потеря ответа не создала дубликат.

## 7. Автоматическая проверка

Команда из папки проекта: `python validate.py` после установки `requirements-dev.txt`.

Скрипт проверяет OpenAPI 3.1 специализированным валидатором, разрешает все локальные ссылки, проверяет схемы и каждое использование примера с проверкой форматов. Дополнительно проверяются 30 отрицательных случаев: неизвестные/серверные поля, пустой PATCH, null, неверные UUID/date/email, отрицательный фонд и недопустимая форма ISBN.

Результаты запуска записаны после выполнения в `VALIDATION.txt`. Проверки схем не заменяют будущие интеграционные проверки остатков, UTC, JWT, TTL, конкурентных запросов и replay.
